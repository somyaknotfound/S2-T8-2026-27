% ================================================================ ABSTRACT
\setcounter{page}{1}
\begin{abstract}
Named Data Networking (NDN) lets every router cache the Data packets it forwards, but a cache
answers only with the exact object that was named~\cite{zhang2014ndn}. Similarity caching relaxes
this rule: on a miss, a cache may return the most similar object it holds, which suits image
retrieval, recommendation and the semantic caching of large language model
queries~\cite{neglia2022similarity,schroeder2025vcache}. The user accepts the answer only if it is
similar enough, and otherwise asks again. In a multi-hop network this raises four problems: a cache
does not know the similarity the user will accept; NDN returns Data only under the name of the
pending Interest; cache contents do not change between retries, so a rejected user keeps getting
the same answer; and the value of a nearby answer depends on queueing and loss upstream. Nakamura
and Kamiyama~\cite{nakamura2024analysis} model the delivery delay on general cache networks, but
assume one fixed answer probability $\alpha$, lossless links of infinite bandwidth and retries that
redraw cache contents independently. We propose threshold-aware similarity caching for NDN,
implemented in ns-3 with ndnSIM~\cite{mastorakis2017ndnsim}. Interests either carry the user's
minimum similarity or name the caches whose answers were rejected, and a delay-aware cache answers
or forwards by weighing the expected cost of a rejection against its measured upstream delay. The
objectives are (i) to reproduce the base paper at packet level and measure the delay when contents
persist across retries, (ii) to bound retries with threshold-carrying and exclusion Interests and
derive their delay in closed form, and (iii) to design a congestion- and loss-aware answer-or-forward
rule and compare it with fixed-$\alpha$ caching. So far, the simulator agrees with the analytical
model in all 18 configurations of the base paper's setting. With persistent contents at
$\alpha = 0.9$, the mean delay rises from 80.6~ms to 14.5~s. Threshold-carrying Interests remove
this tail (4.84~ms, one attempt). Under backhaul congestion and burst loss, the delay-aware rule
beats the best fixed $\alpha$ at every operating point, by 2.8 to 20.8~ms.
% 18 configs + 80.6 ms / 14.5 s: research/results/stage2/analysis.md (24 cells; s = 0.99 and 1.0
% coincide for C = 100). 4.84 ms: stage3/summary.csv (threshold, 0.9, 1.0, per-request).
% 2.8-20.8 ms: stage4/analysis.md (load -2.76 ... -7.02, loss -5.79 ... -20.77 ms).
\end{abstract}

\vspace{1em}

% ================================================================ 1 INTRODUCTION
\section{Introduction}\label{sec:intro}

\subsection{Background}
Caching places copies of popular objects close to users, so that requests are served in fewer hops,
with lower delay and less traffic on the upstream links. Information-Centric Networking makes
caching a function of the network itself. In Content-Centric Networking~\cite{jacobson2009ccn} and
its successor, Named Data Networking (NDN)~\cite{zhang2014ndn}, a consumer sends an Interest packet
that names the data it wants. Any router on the path may answer from its Content Store, and the Data
packet returns along the reverse path, where each router may keep a copy. Many caching and
placement methods have been designed for NDN routers~\cite{chaudhary2026ndncaching}, and they share
one rule: a cache answers only when it holds the exact object named in the Interest. Similarity
caching relaxes this rule. On a miss, a cache may return the stored object most similar to the
request, trading some accuracy for a shorter path. The idea first appeared in metric caches for
content-based image search~\cite{falchi2008metric} and in nearest-neighbour caches for contextual
advertising~\cite{pandey2009nn}. It has since been studied as a general caching problem, with uses
in multimedia retrieval, recommender systems and the serving of machine-learning
models~\cite{neglia2022similarity}. Its most active use today is the semantic caching of large
language model (LLM) queries, where a stored answer to a semantically similar prompt replaces a
costly inference~\cite{bang2023gptcache,gill2025meancache,schroeder2025vcache}. In all these
systems the user, or the application acting for the user, checks whether the answer is similar
enough, and asks again if it is not. What the user experiences is therefore not the hit ratio of
one cache, but the delay until an acceptable answer arrives.

\subsection{Challenges and Issues}
Moving similarity caching from a single server into a multi-hop network raises four issues. First,
a cache does not know how similar an answer must be. If it answers blindly, as in the model of
Nakamura and Kamiyama~\cite{nakamura2024analysis}, an answer the user is sure to reject still costs
a round trip and a retry interval $\delta$, and the retry may be answered the same way. Second,
cache contents do not change in the few milliseconds between two attempts. A user whose nearby
caches hold only unacceptable objects keeps receiving the same rejected answers, so the attempts
are correlated, not independent. In the base paper's own setting, this correlation raises the mean
delay up to 2.1 times at $\alpha = 0.5$ and up to about 1700 times at $\alpha = 0.9$, compared with
the model's prediction.
% research/results/retry_correlation.txt: ratio 2.13 (alpha 0.5) and 1701.67 (alpha 0.9), Monte
% Carlo over 800 configurations; exact enumeration gives 2.13 and 1705.7 (build/matlab/delay_models.m).
Third, NDN delivers a Data packet only if its name matches the pending Interest~\cite{zhang2014ndn},
so a cache cannot return a substitute object under that object's own name; the substitute must
travel in a form the forwarders accept. Fourth, the value of a nearby but approximate answer
depends on the path upstream. When the backhaul is congested or loses packets in
bursts~\cite{gilbert1960capacity,elliott1963estimates}, forwarding is slow and a local answer is
worth more; when the upstream is idle, forwarding is cheap and an approximate answer is rarely worth
the risk of rejection. A cache must therefore estimate its upstream delay online, as TCP does for
its retransmission timer~\cite{jacobson1988congestion,paxson2011rfc6298}. The best answer
probability then changes with load and with the cache's position on the path. All four effects
show only at the packet level, which needs a similarity Content Store and a new forwarding
strategy inside an NDN simulator~\cite{mastorakis2017ndnsim}.

\subsection{Existing Approaches and Their Issues}
Most work on similarity caching studies one cache: what it should store and how often it hits.
This includes metric caches for search~\cite{falchi2008metric}, nearest-neighbour
caching~\cite{pandey2009nn}, the theory and dynamic policies of Neglia et
al.~\cite{neglia2022similarity}, online policies with approximate indexes~\cite{sisalem2023acai},
hit-rate models based on time-to-live (TTL) approximations~\cite{benmazziane2024ttl} and learned
per-prompt thresholds for LLM caches~\cite{schroeder2025vcache}. Network approaches place content
across several similarity caches~\cite{garetto2021placement} or learn cooperative policies at edge
nodes~\cite{wang2025bandit}. They optimise a cost, offline or online, but do not model users who
reject an answer and retry. The only model of the user-level delay over a path of caches is that of
Nakamura and Kamiyama~\cite{nakamura2024analysis}. It fixes one answer probability $\alpha$ at every
cache, assumes lossless links of infinite bandwidth, treats each retry as an independent draw of
cache contents, and is evaluated numerically only. None of these approaches tells a cache whether to
answer approximately or forward, given the user's tolerance and the current state of the upstream
path. None is evaluated in a packet-level network simulator.

\subsection{Problem Statement}
Given a Named Data Network of similarity caches whose users accept an answer only above their own
similarity threshold, and whose upstream links may be congested and lossy, design the request
signalling and a per-cache answer-or-forward rule that bound the number of retries and minimise the
mean delay until an acceptable answer arrives. Derive this delay in closed form where possible, and
validate the design at packet level in ns-3 with ndnSIM.

\subsection{Objectives}
\begin{enumerate}[label=\textbf{O\arabic*.}]
  \item Implement similarity caching with consumer retries in ns-3/ndnSIM, reproduce the base
        paper's delay model on its tandem topology, and measure the delay when cache contents
        persist across retries.
  \item Design threshold-carrying and exclusion Interests that bound retries, and derive their
        delay in closed form.
  \item Design a delay-aware answer-or-forward rule that learns user acceptance and upstream delay
        online, and compare it with fixed-$\alpha$ caching under backhaul congestion and burst loss,
        on mean and tail delay, delivered similarity and upstream traffic.
\end{enumerate}

\subsection{Early Similarity Caches (Falchi et al., 2008; Pandey et al., 2009)}
Falchi et al.~\cite{falchi2008metric} put a cache in front of a content-based image search engine:
a new query close to a cached one is answered from the stored results of past nearest-neighbour
queries. Pandey et al.~\cite{pandey2009nn} apply the idea to contextual advertising, where a
request hits if a similar page is cached; they give caching policies for two efficiency--accuracy
objectives and bound the gain under a generative model of page requests.

\pros First evidence that similar requests can share answers, cutting back-end load.\\
\cons One cache before one server, a fixed answer rule, and no network delay.

\subsection{Placement in Networks of Similarity Caches (Garetto et al., 2021)}
Garetto, Leonardi and Neglia~\cite{garetto2021placement} move to networks: a request is forwarded
along a path of similarity caches, and objects are placed so that the path as a whole gives the best
efficiency--accuracy trade-off. Offline placement is NP-hard; polynomial algorithms approach the
optimum in discrete cases, and a continuous formulation has a simple optimal structure on trees.

\pros A network view of similarity caching, with structural results.\\
\cons Offline placement with a fixed cost per hop: no queueing, loss, retries or protocol.

\subsection{Similarity Caching: Theory and Algorithms (Neglia et al., 2022)}
Neglia, Garetto and Leonardi~\cite{neglia2022similarity} analyse one similarity cache in the
offline, adversarial and stochastic settings: a similar object costs a loss of utility that grows
with dissimilarity, and a miss costs a retrieval cost. They propose the first dynamic policies with
optimality guarantees.

\pros A rigorous cost model, and dynamic policies with guarantees.\\
\cons One cache; retrieval cost is not a measured delay, and users never reject or retry.

\subsection{Ascent Similarity Caching with Approximate Indexes (Si Salem et al., 2023)}
Si Salem, Neglia and Carra~\cite{sisalem2023acai} propose A\c{C}AI for edge servers: an approximate
index of the whole catalogue decides what to serve locally and what to fetch from the remote server,
and mirror ascent updates the cached set, with guarantees even when requests have no statistical
regularity.

\pros Guarantees under adversarial requests; practical approximate indexes.\\
\cons One edge cache; the congested, lossy path to the remote server is not modelled.

\subsection{TTL Model for an LRU-based Similarity Cache (Ben Mazziane et al., 2024)}
Ben Mazziane et al.~\cite{benmazziane2024ttl} extend the time-to-live (TTL) approximation of classical
caching to an LRU-based similarity caching policy. A TTL cache model, tuned through a fixed-point
system of equations to mimic the policy, gives its hit rate without simulation.

\pros Tractable hit rates, which could replace the random contents of network models.\\
\cons One cache, and the hit rate only: neither delay nor a network is modelled.

\subsection{Similarity Caching on Cache Networks (Nakamura and Kamiyama, 2024)}
In our base paper~\cite{nakamura2024analysis}, a request follows a fixed path of caches towards the
origin. On a miss, each cache answers with its most similar object with probability $\alpha$ and
forwards otherwise. The client accepts only a similarity of at least $s$; otherwise it waits
$\delta$ and asks again. With $\rho$ the probability that an attempt is accepted, and $d^{\ge}$ and
$d^{<}$ the mean delays of accepted and rejected attempts, the mean delivery delay, evaluated
numerically on a tandem of five caches, is
\begin{equation}
  \mathbb{E}[D] = d^{\ge} + \bigl(1/\rho - 1\bigr)\bigl(d^{<} + \delta\bigr).
  \label{eq:paper}
\end{equation}
Re-deriving the model, we found three problems. The printed path delay, Eq.~(6), uses only the
last-hop round trip, but the figures use the cumulative one; with that correction we match
Fig.~5(a) at $s = 1$ for $\alpha$ = 0.1 and 0.5 (9.96, 45.97~ms) and come close at $\alpha = 0.9$
(80.6~ms). Eqs.~(8) and~(10) appear to describe different caches, one that knows $s$ and one that
is blind. Most importantly, Eq.~\eqref{eq:paper} averages $\rho$ as if each retry redrew the cache
contents; when contents persist, the mean number of attempts is
$\mathbb{E}[1/\rho] \ge 1/\mathbb{E}[\rho]$ (Jensen), so the model underestimates the delay.
% 9.96 / 45.97 / 80.62 ms: research/results/retry_correlation.txt, "model ms" at s = 1.

\pros The first closed-form, user-level delay metric over a path of caches, with retries.\\
\cons One global $\alpha$, even for exact hits; ideal links; independent retries; numerical only.

\subsection{Similarity Caching in Cooperative Edge Networks (Wang et al., 2025)}
Wang et al.~\cite{wang2025bandit} study edge nodes that cooperatively serve requests over
fluctuating links. Casting caching as an adversarial multi-armed bandit, their online policy MABSCP
updates the cached sets from real-time feedback to minimise a cost that balances similarity
against delivery latency.

\pros Cooperative and online; latency is part of the cost, and the policy adapts to change.\\
\cons Decides what to cache, not whether to answer; no measured latency, no retries.

\subsection{Verified Semantic Prompt Caching (Schroeder et al., 2025)}
vCache~\cite{schroeder2025vcache} reuses a stored LLM response when a new prompt's embedding is
close to a cached one. Instead of one static similarity threshold, it learns online a threshold for
each cached prompt, so that the cache meets an error rate set by the user.

\pros It answers only when acceptance is likely, learned from feedback: closest to our rule.\\
\cons One server-side cache; it controls correctness, not delay, and has no network path.

\section{Proposed Approach}\label{sec:approach}

\subsection{System Model}\label{sec:system}
We keep the base paper's tandem, so results compare with its model, and add what it leaves out
(Fig.~\ref{fig:system}). Five caches and an origin are joined by 1~Gbps links with a 1~ms delay,
and client $c_i$ runs on cache $v_i$. The catalogue has $C = 100$ items, each cache holds
$B = 10$, and a rejected client retries after $\delta = 10$~ms. For congestion, the link from $v_5$
to the origin becomes a 2~Mbps backhaul with a 100-packet DropTail queue, shared with Poisson cross
traffic from $v_1$. For loss, every link drops packets in bursts following a Gilbert--Elliott
model~\cite{gilbert1960capacity,elliott1963estimates} with a mean burst of 3.3 packets. NDN's name
matching is unchanged: a substitute item travels inside a Data packet named after the full
Interest, and the payload says which item it is and how similar.

\subsection{Answer-or-Forward Policies}\label{sec:policies}
At cache $v$, an Interest for item $c$ meets the most similar stored item $c'$, with similarity
$s'$; the cache answers with $c'$ or forwards, under one of four rules.
\begin{itemize}
  \item \textbf{Blind} (the base paper): answer with probability $\alpha$.
  \item \textbf{Threshold}: the Interest carries the user's threshold $s$, and $v$ answers only if
        $s' \ge s$ (and its $\alpha$ coin agrees). Nothing is rejected, so a request takes one
        attempt and the paper's Eq.~(8) becomes exact. With $p_i$ the probability that the $i$-th
        cache on the path holds an acceptable item, $q_i = \alpha p_i$, $m$ caches before the
        origin and link delay $\tau$,
        \begin{equation}
          \mathbb{E}[D_{\mathrm{thr}}] = \sum_{i=1}^{m} 2\tau(i-1)\,q_i\prod_{j<i}(1-q_j)
          \;+\; 2\tau m\prod_{j=1}^{m}(1-q_j).
          \label{eq:threshold}
        \end{equation}
  \item \textbf{Exclusion}: caches stay blind, but a retry lists the caches whose answers were
        rejected, and they forward; a request needs at most $m+1$ attempts.
  \item \textbf{Delay-aware} (ours): let $\Dup$ be the measured delay of forwarding, $R_h$ the round
        trip to a client $h$ hops away and $F_v(s')$ the share of $v$'s users who accept $s'$.
        Answering costs $R_h$ plus, with probability $1-F_v(s')$, a rejection
        ($\delta + R_h + \Dup$); forwarding costs $R_h + \Dup$. So $v$ answers iff
        \begin{equation}
          \bigl(1-F_v(s')\bigr)\bigl(\delta + R_h + \Dup\bigr) < \Dup
          \iff
          s' \ge s^{*}_v = F_v^{-1}\!\Bigl(1 - \frac{\Dup}{\delta + R_h + \Dup}\Bigr).
          \label{eq:rule}
        \end{equation}
\end{itemize}

\subsection{Delay-Aware Algorithm}\label{sec:algo}
In Algorithm~\ref{alg:delay-aware}, $\Dup$ is a smoothed round trip with gain $1/8$, as in
TCP~\cite{jacobson1988congestion,paxson2011rfc6298}; an expired Interest counts as the time lost,
so $\Dup$ also sees loss. $F_v$ uses 20 similarity bins with a Laplace prior, fitted to be
non-decreasing. A retry naming $v$ is a rejection and no retry within a window $W$ an acceptance.
The verdict is uncertain while Eq.~\eqref{eq:rule} differs at $F_v \pm 2$ standard errors, so
exploration stops once each bin is settled.

\begin{algorithm}[H]
\caption{Delay-aware answer-or-forward at cache $v$}
\label{alg:delay-aware}
\begin{algorithmic}[1]
\Require Interest $I$ for item $c$ from a client $h$ hops away, exclusion list $E(I)$; store
         $\mathcal{B}_v$; estimates $\Dup$, per-hop round trip $r$ and $F_v$
\State $c' \gets \arg\max_{x \in \mathcal{B}_v} \mathrm{sim}(c, x)$; \quad
       $s' \gets \mathrm{sim}(c, c')$; \quad $R_h \gets h\, r$
\If{$v \in E(I)$} \Comment{\textit{our earlier answer was rejected}}
  \State record a rejection for the similarity $v$ served; forward $I$
\ElsIf{$s' = 1$ \textbf{or} $(1-F_v(s'))(\delta + R_h + \Dup) < \Dup$ \textbf{or} the verdict is
       uncertain}
  \State send Data$(\mathrm{name}(I);\, c', s', h)$ downstream; remember $(I, s', t_{\mathrm{now}})$
\Else
  \State $t_{\mathrm{fwd}}(I) \gets t_{\mathrm{now}}$; forward $I$ upstream
\EndIf
\Statex \textbf{on} Data or expiry for a forwarded $I$:
        $\Dup \gets \tfrac{7}{8}\Dup + \tfrac{1}{8}\bigl(t_{\mathrm{now}} - t_{\mathrm{fwd}}(I)\bigr)$;
        update $r$
\Statex \textbf{on} no retry naming $v$ within $W$ of an answer: record an acceptance for its $s'$
\end{algorithmic}
\end{algorithm}

\subsection{Justification}\label{sec:justify}
\begin{itemize}
  \item \textbf{Bounding retries.} With blind caches and persistent contents, a user whose $m$
        caches hold nothing acceptable succeeds only if all forward, with probability
        $(1-\alpha)^m = 10^{-5}$ at $\alpha = 0.9$: in our simulation the mean delay at $s = 1$
        rises from the model's 80.6~ms to 14.5~s.
        % research/results/stage2/analysis.md (0.9, 1.0: model 80.62 ms; per-request 14521.56 ms).
  \item \textbf{$\alpha$ becomes obsolete.} In Eq.~\eqref{eq:threshold}, raising $q_i$ moves
        probability from outcomes with delay $\ge 2\tau i$ to one with delay $2\tau(i-1)$, so the
        delay falls strictly in $\alpha$: $\alpha = 1$ is optimal.
  \item \textbf{Privacy and adaptation.} Exclusion and the delay-aware rule keep the user's
        threshold at the client; Eq.~\eqref{eq:rule} always serves an exact hit. Upstream
        congestion or loss raises $\Dup$ and lowers $s^{*}_v$, so the cache answers locally more.
  \item \textbf{Platform.} NFD's Content Store matches exact names before the strategy runs, so our
        strategy does the similarity lookup and NFD is unchanged. In ndnSIM~2.9, NDN packets bypass
        ns-3's traffic control, so congestion is a DropTail queue; we claim nothing about RED or CoDel.
\end{itemize}
